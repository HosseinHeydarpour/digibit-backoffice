# دسته‌بندی‌ها / Categories

صفحهٔ درخت دسته‌ها (BO-G01): دادهٔ تودرتوی `GET /categories?tree=true` در دو سطح رندر می‌شود و
هر ردیف نام، آیکون، تعداد محصول و وضعیت فعال/غیرفعال را نشان می‌دهد (نامک عمداً در ردیف نیست؛ در فرم قابل ویرایش است).

The category tree screen (BO-G01): nested `GET /categories?tree=true` data renders as two levels of
plain lists, and every row carries the name, icon, product count and active/inactive pill.

## کاربرد / Use case

برای دیدن ساختار فروشگاه و اینکه هر شاخه چند محصول دارد. وقتی تعداد دسته‌ها کم است (چند ده) این
صفحه درست است؛ درختی با هزار گره به مجازی‌سازی `p-tree` و صفحه‌بندی سمت سرور نیاز دارد که فاز بعدی
است.

Use it to read the shop's structure and how many products each branch holds. It fits a catalogue of
a few dozen categories; a thousand-node tree would need `p-tree` virtual scrolling and server-side
paging, which is out of scope here.

## رفتارها / Behaviour

- **فیلتر در مرورگر، با حفظ سلسله‌مراتب.** `filterTree` یک تابع خالص است: گره‌ای که خودش یا یکی از
  فرزندانش با جستجو بخواند می‌ماند، و والدِ یک گرهٔ منطبق هم می‌ماند تا درخت یتیم نشود (tc 6).
- **جستجوی بی‌نتیجه با جستجوی «فروشگاه خالی» قاطی نمی‌شود.** اولی «دسته‌ای با این جستجو پیدا نشد» با
  دکمهٔ پاک کردن است، دومی حالت خالی واقعی با دعوت به ساخت دسته (tc 8).
- **`null` و `[]` دو جواب متفاوت‌اند.** `null` یعنی هنوز پاسخ نیامده (اسکلت بارگذاری) و `[]` یعنی
  فروشگاه دسته‌ای ندارد؛ همان قاعدهٔ داشبورد و لیست محصولات.
- **خطا با «تلاش دوباره».** `catchError` مقدار `null` برمی‌گرداند و صفحه بلوک خطا را با دکمهٔ
  بازخوانی نشان می‌دهد، نه یک صفحهٔ خالی.
- **در موبایل.** ناحیهٔ درخت داخل کارت اسکرول عمودی دارد (`max-h-[70vh]`)، و بج تعداد/وضعیت زیر
  `sm` پنهان می‌شوند تا نام کنار سه دکمهٔ ردیف (دستهٔ درگ، مداد، سطل) جا شود (tc 9).
- **هر شاخه در بار اول باز است** تا هر دو سطح بدون کلیک دیده شوند (tc 1/2).

- **Filter in the browser, hierarchy intact.** `filterTree` is pure: a node stays when it or a
  descendant matches, and the ancestor of a match stays too, so no orphan floats at the root.
- **A filtered-out result is not an empty shop.** The first says «دسته‌ای با این جستجو پیدا نشد»
  with a clear button; the second is the real empty state.
- **`null` vs `[]`.** `null` is "no answer yet" (skeleton), `[]` is "no categories": the same rule
  the dashboard and the products list follow.
- **Failure has a retry.** `catchError` yields `null` and the page renders the shared error block.
- **On a phone** the tree scrolls inside the card, and the count/status pills hide below `sm` so the
  name fits next to the row's three controls (grip, pencil, trash).
- **Every branch starts open**, so both levels show without a click.

## ایجاد و ویرایش دسته / Create and edit (BO-G02)

دکمهٔ «افزودن دسته» و آیکون مداد هر ردیف، یک دیالوگ مشترک را باز می‌کنند. فرم در همان دیالوگ
می‌ماند تا کاربر از درخت خارج نشود و بعد از ذخیره، درخت دوباره گرفته می‌شود؛ پس ردیف تازه (و آیکون
انتخاب‌شده) بدون رفرش دیده می‌شود.

The «افزودن دسته» button and each row's pencil open one shared dialog. The form stays inside it so
the user never leaves the tree, and a save refetches the tree — the new row (with the icon that was
chosen) appears without a refresh.

- **نامک از نام ساخته می‌شود** (`slugify` مشترک با فرم محصول) و با ویرایش دستی دیگر عوض نمی‌شود.
- **نام تکراری فقط در همان سطح** خطاست: زیر «لوازم تحریر» می‌توان دسته‌ای هم‌نام با یک ریشهٔ دیگر
  ساخت.
- **نامک یکتاست** (چون URL است) و خطای ۴۲۲ سرور زیر همان فیلد می‌نشیند و دیالوگ باز می‌ماند.
- **انصراف هیچ درخواستی نمی‌فرستد** و مقادیر دور ریخته می‌شوند.
- **در موبایل** دیالوگ ۹۵٪ عرض دارد و دکمه‌ها ۴۴px می‌شوند.

## ترتیب و جابه‌جایی / Order and moving (BO-G03)

ترتیب هر سطح از **۱** شروع می‌شود و پیوسته است. جابه‌جایی با **Angular CDK** انجام می‌شود: ردیف را
از دستهٔ ⠿ بگیر و بکش؛ CDK نسخهٔ شناور ردیف، جای خالی مقصد و انیمیشن جابه‌جایی را خودش می‌سازد.
رها کردن داخل فهرست یک دسته، آن را **زیردسته** می‌کند و رها کردن بین ریشه‌ها، آن را **دستهٔ اصلی**.
برای بیرون آوردن یک زیردسته از شاخه‌اش، آن را روی کادر خط‌چین **«برای دستهٔ اصلی کردن…»** زیر درخت
رها کن؛ به انتهای ریشه‌ها اضافه می‌شود. سطح سوم رد می‌شود، `Escape` درگ را لغو می‌کند و رها کردن
بیرون از فهرست، ردیف را به جای اولش برمی‌گرداند. تا وقتی کادر جستجو متن دارد درگ خاموش است، چون
فهرست فیلترشده جای ردیف‌ها را عوض می‌کند.

باز و بسته کردن شاخه: آیکون + نام + پیکان **یک دکمه** هستند، پس کلیک روی هر جای این برچسب شاخه را
باز/بسته می‌کند — نه فقط پیکان. مداد، سطل و دستهٔ درگ دکمه‌های جدا هستند.

Orders start at **1** and stay contiguous per level. Moving uses **Angular CDK**: grab a row by its
⠿ grip; CDK draws the floating preview, the placeholder and the slide animation itself. Dropping
inside a root's list nests the row, dropping between roots makes it a root. To lift a child out of
its branch, drop it on the dashed **«make it a root»** zone under the tree: it is appended to the
roots. A third level is refused, `Escape` cancels, and releasing outside any list puts the row back
where it started. Dragging is off while the search box has text, because the filtered list changes
what an index means.

Expanding a branch: the icon, name and chevron are a **single button**, so clicking anywhere on that
label opens it — not only the chevron. The pencil, the trash and the drag grip are separate controls.

## حذف دسته / Deleting (BO-G04)

حذف یک تصمیم است نه یک تأیید ساده. تصمیم با یک تابع خالص (`deleteDecision`) گرفته می‌شود و یک
دیالوگ آن را نشان می‌دهد:

- **«بدون دسته‌بندی» محافظت‌شده است.** محصول‌های هر دستهٔ حذف‌شده به آن منتقل می‌شوند، پس نه دکمهٔ
  سطل دارد و نه سرور حذفش را قبول می‌کند (tc 1).
- **محصول هیچ‌وقت جلوی حذف را نمی‌گیرد.** تعداد محصول‌های شاخه بالای تأیید نوشته می‌شود
  («N محصول … به «بدون دسته‌بندی» منتقل می‌شوند») تا انتقال بی‌خبر نباشد (tc 2/10).
- **والد دو گزینه دارد.** «انتقال به …» (پیش‌فرض) زیردسته‌ها را یک سطح بالا می‌برد و محصول‌هایشان
  دست‌نخورده می‌ماند؛ «زیردسته‌ها را هم حذف کن» کل شاخه را پاک می‌کند و در حالت انتخاب قرمز می‌شود
  (tc 3/4).
- **همهٔ راه‌های بستن کار می‌کنند** (`visibleChange`): ✕، `Escape` و کلیک روی ماسک. انصراف هیچ
  درخواستی نمی‌فرستد (tc 5)؛ موفقیت toast می‌دهد و درخت را از سر می‌گیرد (tc 9)، پس نامک آزادشده
  دوباره قابل استفاده است (tc 8).

Deleting is a decision, not a confirmation; the pure `deleteDecision` answers which of the three
shapes applies and one dialog renders it:

- **The default «بدون دسته‌بندی» bucket is protected**: deleted categories' products land there, so it
  has no trash button and the API refuses even a stale request (tc 1).
- **Products never block a delete** — the count is printed above the confirmation and the server
  re-buckets them to the default category (tc 2/10).
- **An empty parent gets a choice**: «transfer to …» (the default, loses nothing) or «delete the
  children too» (red when selected) (tc 3/4).
- **Every close path works** (`visibleChange`): ✕, `Escape`, the mask. Cancel sends nothing (tc 5);
  success toasts and refetches the tree (tc 9), so the freed slug can be reused (tc 8).

## والد و آیکون / Parent and icon (BO-G03/G04)

فرم دسته حالا یک سلکت **«دستهٔ والد»** دارد: فقط ریشه‌ها را پیشنهاد می‌دهد (سطح سوم وجود ندارد)، خود
دسته را حذف می‌کند و برای دسته‌ای که زیردسته دارد قفل است.

آیکون‌ها از ۱۲ به ۶۰ گزینه رسیده‌اند و سلکت آیکون **جستجو** دارد (`filter` روی برچسب فارسی)؛ وقتی
چیزی پیدا نشود «موردی پیدا نشد» می‌نویسد، نه متن انگلیسی پیش‌فرض PrimeNG.

هر ریشهٔ باز، حتی بدون فرزند، یک فهرست زیردسته دارد: نوار خط‌چین کوتاهی که تا وقتی چیزی کشیده نشده
شفاف است و در درگ روشن می‌شود. پس یک دستهٔ **تازه** هم با درگ فرزند قبول می‌کند.

The category form now has a **parent select**: roots only (there is no third level), the node itself is
filtered out, and it is read-only for a node that has children. The icon picker grew from 12 to 60
options and is searchable by its Persian label; an empty search says «موردی پیدا نشد» instead of
PrimeNG's English default.

Every expanded root now owns a child list, even an empty one: a short dashed strip that stays
transparent until something is dragged, so a **brand-new** category accepts children by drag too.

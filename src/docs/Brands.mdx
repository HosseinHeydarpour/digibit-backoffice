# برندها / Brands

صفحهٔ برندها (BO-G05): یک لیست صفحه‌بندی‌شده با جستجو، پیل وضعیت، سوییچ فعال/غیرفعال و
دیالوگ ایجاد/ویرایش؛ همان الگوی صفحهٔ دسته‌بندی‌ها، بدون درخت.

The brands screen (BO-G05): a paged, searchable list with a status pill, an active switch and a
create/edit dialog — the categories page's structure without the tree.

## کاربرد / Use case

وقتی فروشگاه چند برند دارد و محصول باید در فیلتر برند دسته‌بندی شود. صفحه برای چند ده برند ساخته
شده؛ لیست هزارتایی به صفحه‌بندی و جستجوی سمت سرور (که همین‌جا هست) و شاید مجازی‌سازی نیاز دارد.

Use it when the shop carries more than a handful of brands and the product filters group by them.
The page is built for a few dozen brands; it already searches and pages on the server, so a
thousand rows would only need virtual scrolling on top.

## رفتارها / Behaviour

- **جستجو debounce دارد و سمت سرور است.** هر عبارت تازه از صفحهٔ ۱ شروع می‌شود و برچسب
  «صفحهٔ ۱ از ۳» از `total` سرور می‌آید، نه از تعداد ردیف‌های بارگذاری‌شده (tc 1).
- **ناوبری صفحه دکمه است، نه لینک.** «قبلی/بعدی» با `disabled` واقعی و متن صفحه، و با یک صفحه
  اصلاً رندر نمی‌شود.
- **سوییچ وضعیت خوش‌بین است.** سوییچ و پیل قبل از پاسخ سرور عوض می‌شوند؛ خطا صفحه را دوباره
  می‌گیرد و پیام خطا از اینترسپتور می‌آید (tc 6). جزئیات در بخش «وضعیت سریع» آمده است.
- **حذف با هشدار تعداد محصول.** اگر برند در محصولی استفاده شده باشد، متن تأیید می‌گوید
  «N محصول بدون برند می‌شوند»؛ خود محصول‌ها حذف نمی‌شوند و از فیلتر برند هم برداشته می‌شوند (tc 7/9).
- **نام و نامک یکتا هستند.** خطای ۴۲۲ سرور زیر همان فیلد می‌نشیند و دیالوگ باز می‌ماند (tc 5).
- **نامک از نام ساخته می‌شود** (`slugify` مشترک) و با ویرایش دستی دیگر عوض نمی‌شود (tc 4).
- **لوگو هنگام ذخیره آپلود می‌شود.** انتخاب فایل فقط پیش‌نمایش ۱:۱ با `blob:` و اعتبارسنجی
  است؛ «ذخیره» اول `POST /media` و بعد برند را با URL می‌فرستد. «انصراف» هیچ درخواستی نمی‌فرستد.
  PNG/SVG/WebP تا ۱ مگابایت؛ «حذف لوگو» مقدار `logo: null` می‌فرستد (tc 1–10).

- **Search is debounced and server-side.** Every query starts at page 1, and the label comes from the
  server's `total`, not from the loaded rows (tc 1).
- **Paging is two real buttons.** They disable at the edges and disappear when there is one page.
- **The status switch is optimistic**; a failure reloads the page and the interceptor reports it (tc 6).
- **Delete warns with the product count**; those products are unbranded, never deleted, and the brand
  leaves the product filter (tc 7/9).
- **Name and slug are unique**; a 422 lands under its field and the dialog stays open (tc 5).
- **The slug follows the name** until edited by hand (tc 4).
- **The logo uploads on save.** Picking a file only validates it and shows a 1:1 `blob:` preview;
  «ذخیره» sends `POST /media` first and then the brand with the returned URL. «انصراف» sends
  nothing. PNG/SVG/WebP up to 1 MB; «حذف لوگو» saves `logo: null` (tc 1–10).

## وضعیت سریع / Quick status (BO-G07)

- **سوییچ در ستون وضعیت است، نه ستون عملیات.** یک سوییچ برای هر ردیف، در همهٔ عرض‌ها؛ در موبایل
  وقتی سوییچ رندر شده باشد (کاربر با `products.view`) پیل متن پنهان می‌شود و همان سوییچ وضعیت را
  نشان می‌دهد، پس بدون اسکرول افقی در دسترس است. کاربر بدون مجوز همان پیل را می‌بیند.
- **تغییر خوش‌بینانه است.** سوییچ و پیل پیش از پاسخ عوض می‌شوند؛ خطا صفحه را دوباره می‌گیرد
  (rollback) و پیام موفقیت را همین صفحه می‌دهد. خطا را اینترسپتور نشان می‌دهد و اینجا تکرار نمی‌شود.
- **آفلاین با `writeValue` برمی‌گردد.** PrimeNG پیش از `onChange` مقدار خود را عوض می‌کند، پس handler
  پیش از هشدار سوییچ را به وضعیت واقعی ردیف برمی‌گرداند و هیچ درخواستی نمی‌فرستد.
- **۴۴px در موبایل، بدون تغییر اندازهٔ track.** سوییچ track طبیعی ۴۰×۲۴ دارد و یک `<label>` با
  `max-sm:size-11` جعبهٔ لمس ۴۴×۴۴ می‌سازد؛ نام قابل‌دسترس ثابت است («وضعیت برند …»).
- **دسترسی با `products.view`.** بدون این مجوز سوییچ و عملیات ردیف رندر نمی‌شوند و
  `toggleStatus` مستقیم هم کاری نمی‌کند.

The switch sits in the status cell, not the actions cell: one switch per row at every width. On a
phone the text pill hides when the switch is rendered (a user with `products.view`), so the switch
carries the state without horizontal scrolling; a read-only user keeps the pill. The
flip is optimistic — switch and pill change before the answer; a failure reloads the page as the
rollback and the page shows the success toast, while the interceptor owns the error message. Offline,
PrimeNG has already changed its own value before `onChange`, so the handler calls `writeValue` with
the row's real flag before the warning and sends nothing. The natural 40×24 track keeps its size; a
`<label class="max-sm:size-11">` wrapper supplies the 44px phone hit box, and the accessible name is
stable («وضعیت برند …»). `products.view` gates the switch and row actions, and `toggleStatus` returns
early even if called directly.

## منطق آپلود / Upload logic (BO-G06)

1. **آپلود در لحظهٔ ذخیره، نه انتخاب فایل.** دیالوگ یک تراکنش است: انتخاب فایل فقط پیش‌نمایش
   `blob:` و اعتبارسنجی است، و «انصراف» نباید فایل یتیم روی سرور بگذارد. اگر آپلود موفق شود و
   ذخیرهٔ برند شکست بخورد، فایل یتیم می‌ماند و پاک‌سازی‌اش با سرور است (`contract.md §۱.۴`).
2. **مالکیت blob.** فرم فقط blobی را revoke می‌کند که خودش با `URL.createObjectURL` ساخته است.
   URL برگشتی سرور — که در mock هم یک `blob:` است — دست‌نخورده می‌ماند؛ وگرنه ردیف لیست بعد از
   ذخیرهٔ موفق می‌شکند.
3. **چرا mock یک blob برمی‌گرداند.** mock نه CDN دارد نه فایل را ذخیره می‌کند؛ URL با رفرش
   می‌رود. بک‌اند واقعی URL مطلق می‌دهد (`contract.md §۲`).
4. **محدودیت‌ها.** حداکثر ۱ مگابایت و فقط PNG/SVG/WebP؛ اعتبارسنجی نهایی سمت سرور است. SVG
   باید سمت سرور sanitize شود و کلاینت آن را فقط در `<img>` نشان می‌دهد.

**English**

1. **Upload on save, not on pick.** The dialog is a transaction: picking a file only produces a
   `blob:` preview and a local validation, and «انصراف» must not leave an orphan on the server.
   If the upload succeeds and the brand write then fails, the file is orphaned and cleanup belongs
   to the server (`contract.md §1.4`).
2. **Blob ownership.** The form revokes only the blob it created with `URL.createObjectURL`. The
   URL returned by the server — also a `blob:` in the mock — is left untouched, or the saved row
   in the list would break.
3. **Why the mock returns a blob.** It has no CDN and stores no file, so the URL disappears on
   refresh. The real backend returns an absolute URL (`contract.md §2`).
4. **Limits.** At most 1 MB and only PNG/SVG/WebP; the server is the final validator. SVG must be
   sanitised server-side, and the client only ever shows it in an `<img>`.

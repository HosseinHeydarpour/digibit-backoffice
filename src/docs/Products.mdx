# ماژول محصولات / Products module

مسیرها و اسکلت ماژول محصولات (BO-F01). صفحهٔ لیست در BO-F02 ساخته شد؛ فرم ایجاد مطابق قالب
`admin-panel-add-product.html` در BO-F07 ساخته می‌شود.

The routes and scaffold of the products module (BO-F01). The list page has been built (BO-F02);
the create form (matching `admin-panel-add-product.html`) arrives in BO-F07.

## Use case

این صفحه **چرا و چگونه** مسیرها ساخته شده‌اند را مستند می‌کند، نه یک کامپوننت بصری — برای دیدن
جدول محصولات، story `Features/Products/ProductList` را باز کنید. برای دنبال‌کردن مسیرِ یک URL در
router، کامنت `TRACE` در `products.routes.ts` را بخوان.

This page documents **why and how** the routes are wired, not a visual component — for the products
table itself, open the `Features/Products/ProductList` story. To trace a URL through the router,
read the `TRACE` comment in `products.routes.ts`.

## How to use

| Route                | Page            | Real content           |
| -------------------- | --------------- | ---------------------- |
| `/products`          | `ProductList`   | list table — BO-F02    |
| `/products/new`      | `ProductCreate` | create form — BO-F07   |
| `/products/:id/edit` | `ProductEdit`   | edit form — BO-F07     |
| `/products/:id`      | `ProductDetail` | detail — later F tasks |

هر route در `products.routes.ts` اعلام شده و `loadChildren` آن را lazy می‌کند (chunk
`products-routes`). هر route `data.title` (عنوان topbar)، `data.breadcrumb` و
`data.permission: 'products.view'` را دارد.

Every route is declared in `products.routes.ts` and `loadChildren` loads it lazily (the
`products-routes` chunk). Each carries `data.title` (topbar heading), `data.breadcrumb`
and `data.permission: 'products.view'`.

## Logic

حرف اول `new` پیش از `:id` می‌آید تا به‌عنوان یک id گرفته نشود؛ `:id/edit` دو بخش دارد و هرگز
با `:id` (یک بخش) تداخل نمی‌کند، چون شمار بخش‌ها فرق دارد. گیتینگ مجوز روی route هنوز اعمال
نمی‌شود — guard مربوطه BO-D07 است؛ `data.permission` فقط ثابتِ آماده برای آن است.

The literal `new` precedes `:id` so it is never captured as an id; `:id/edit` has two segments and
can never be shadowed by `:id`, because the segment counts differ. Route permission gating is not
enforced yet — the guard is BO-D07, and `data.permission` is only the constant it will read.

## The list page (BO-F02)

ستون‌ها در یک آرایهٔ `cols` با `field/header/width/sortable` تعریف شده‌اند و داده با signal از
`ProductsService` می‌آید، بنابراین فیلترهای BO-F03 بدون رفرش صفحه اعمال می‌شوند. خروجی fetch از
یک `state()` می‌گذرد — `error > loading > empty > data` (BO-E07) — و صفحهٔ خالی همان
`<app-empty-state>` مشترک را با دکمهٔ «افزودن محصول» نشان می‌دهد.

Columns are declared in a `cols` array carrying `field/header/width/sortable` and data arrives as a
signal from `ProductsService`, so BO-F03's filters apply without a page refresh. The fetch's outcome
goes through one `state()` — `error > loading > empty > data` (BO-E07) — and the empty shop renders
the shared `<app-empty-state>` with an «افزودن محصول» action.

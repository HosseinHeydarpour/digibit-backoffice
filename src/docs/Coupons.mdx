# کوپن تخفیف / Coupons

فهرست کدهای تخفیف (BO-J01): کد با دکمهٔ کپی، نوع (درصدی/مبلغی)، مقدار، بازهٔ اعتبار شمسی،
نسبت استفاده و وضعیت مشتق‌شده. ساخت و ویرایش کوپن در BO-J02/BO-J03 و کلید فعال/غیرفعال در
BO-J04 به همین ماژول اضافه می‌شود.

The coupon list (BO-J01): code with a copy button, type (percent/amount), value, Solar validity
window, usage ratio and a derived status. Create/edit arrives in BO-J02/J03 and the enable switch
in BO-J04.

## کاربرد / Use case

وقتی بازاریابی یک کد تخفیف می‌سازد و پشتیبانی باید بفهمد چرا کد کار نمی‌کند: منقضی شده، سقفش
پر شده، یا دستی خاموش شده است. سه عدد پشت هر ردیف (بازه، استفاده، وضعیت) دقیقاً همین را می‌گویند.

Use it when marketing adds a code and support needs to know why it stopped working: expired, out
of redemptions, or switched off. The three facts on each row (window, usage, status) answer exactly
that.

## رفتارها / Behaviour

- **وضعیت ذخیره نمی‌شود.** `couponStatus()` هر بار از `to`، `usedCount` و `isActive` مشتق
  می‌شود، با اولویت منقضی > تمام‌شده > غیرفعال > فعال. فیلتر، بج و کلید (BO-J04) از همین یک
  تابع می‌خوانند.
- **کپی بی‌سروصدا شکست می‌خورد.** اگر `navigator.clipboard` نبود یا مسدود شد، آیکون به تیک
  نمی‌رود و پیام خطا هم نمی‌آید؛ این یک اکشن راحتی است، نه یک عملیات داده.
- **یک `viewState()` با چهار پایان:** `error > loading > empty > data`. `null` اسکلتون است،
  نه فهرست خالی.
- **فیلتر و صفحه‌بندی در state کامپوننت‌اند، نه URL.** یک سلکت و یک شمارهٔ صفحه است و لینک
  اشتراکی فیلتر کوپن نیاز نیست؛ اگر شد، `coupon-paging.ts` شکل URL را آماده دارد.
- **موبایل:** نوع زیر `sm` و بازه زیر `md` پنهان می‌شوند؛ کد، مقدار، استفاده و وضعیت می‌مانند.

**English**

- **The status is derived, never stored.** `couponStatus()` reads `to`, `usedCount` and
  `isActive` with expired > exhausted > inactive > active precedence; the filter, the badge and
  the BO-J04 switch all call it.
- **Copy fails quietly.** A missing or blocked `navigator.clipboard` leaves the icon alone and
  shows no error toast; it is a convenience action, not a data operation.
- **One `viewState()` with four outcomes:** error > loading > empty > data. `null` is the
  skeleton, not an empty list.
- **The filter and paging are component state, not URL.** There is one select and one page
  number, and a shareable coupon filter is not a requirement; `coupon-paging.ts` already has the
  URL shape if that changes.
- **Mobile:** type below `sm` and the window below `md` hide; code, value, usage and status stay.

## قواعد اعتبار / Validation rules

- **درصد ۱ تا ۱۰۰، مبلغ بزرگ‌تر از صفر.** `couponValueValidator` یک گروه‌ولیدیتور است چون به
  `type` نگاه می‌کند؛ خطا روی خود فیلد `value` نوشته می‌شود تا `app-form-field` و `fieldError()`
  یک جا بخوانند.
- **پایان بعد از شروع.** `couponDateRangeValidator` دو تاریخ جلالی را مقایسه می‌کند (هر دو در
  کنترل به‌صورت میلادی `YYYY-MM-DD` هستند).
- **کد ۳ تا ۲۰ کاراکتر `[A-Z0-9-]`.** حروف کوچک پذیرفته و به بزرگ تبدیل می‌شوند، چون همان کدی
  است که ذخیره می‌شود. یکتایی کد سمت سرور است و 422 به زیر فیلد `code` می‌رسد.
- **سقف استفاده و حداقل سبد** با `Validators.min` کنترل می‌شوند؛ «سقف هر کاربر» خالی مجاز است.
- **هشدار، نه خطا:** اگر کوپن مبلغی از حداقل سبدش بیشتر باشد، فرم یک خط زرد نشان می‌دهد؛
  ذخیره را نمی‌بندد، چون کوپن کار می‌کند و فقط سخاوتمندانه است.
- **خطاها فقط بعد از touched.** `fieldError()` تا لمس‌نشدن فیلد چیزی چاپ نمی‌کند (tc 9).

**English**

- **Percent 1..100, amount > 0.** `couponValueValidator` is a group validator because it reads
  `type`; the key is written onto the `value` control so FormField and `fieldError()` read one
  place.
- **End after start.** `couponDateRangeValidator` compares the two Jalali picks (both controls hold
  Gregorian `YYYY-MM-DD`).
- **Codes are 3..20 chars of `[A-Z0-9-]`.** Lowercase is accepted and uppercased because that is
  what gets stored; uniqueness is the server's call and a 422 lands under `code`.
- **Caps and minimum cart** use `Validators.min`; the per-customer cap may be empty.
- **A warning, not an error:** an amount coupon bigger than its minimum cart shows a yellow line
  and still saves.
- **Errors appear after `touched`.** `fieldError()` prints nothing before the field is touched.

## فرم ایجاد/ویرایش / Create and edit

فرم (BO-J02): کد با دکمهٔ تولید، نوع، مقدار، بازهٔ جلالی، سقف کل و هر کاربر، حداقل سبد و
توضیحات. یک فرم برای هر دو حالت؛ دیالوگ هر بار کامپوننت را از نو می‌سازد، پس ویرایشِ لغوشده به
فرم بعدی نشت نمی‌کند.

The form (BO-J02): code with a generator, type, value, Jalali window, total and per-customer caps,
minimum cart and a description. One form for both modes; the dialog re-creates the component each
time, so a cancelled edit does not leak into the next one.
